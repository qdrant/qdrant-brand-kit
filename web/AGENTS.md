# Web (for agents)

`@qdrant/web` is Qdrant's website section library: every section a site the size of qdrant.tech needs (navigation, heroes, features, proof, pricing, FAQ, calls to action, listings, footers and more), built from the [design system](../design-system/), with variants, docs and a page builder in the studio's Web page (Juan, 2026-11-21). The qdrant.tech website itself lives in another repo; this is where its sections are designed, documented and reviewed. The work is code-first: a section is built and approved here, and goes to Figma afterwards.

Read these first. Their rules apply here too:

1. The [root `AGENTS.md`](../AGENTS.md).
2. [`design-system/AGENTS.md`](../design-system/AGENTS.md), including which "Never" rules apply to web UI.

## Rules for sections

- **Build from the design system.** Import components from `@qdrant/design-system`. A section never sets its own colors, fonts or radii.
- **Page layout** follows [`primitives/spacing/`](../primitives/spacing/), "Web and landing page layout": a 1440px design width and a **1200px content container** (Juan, 2026-11-21; it was 1110px), 24px between columns, vertical section padding of 80 to 120px, never less than 80px, and 40 to 64px between a heading block and its content. `Section` applies it.
- **Breakpoints** come from [`primitives/breakpoints/`](../primitives/breakpoints/).
- **Pattern backgrounds** come from [`brand-assets/patterns/`](../brand-assets/patterns/), with its rules: they bleed off every edge, violet by default and red only with a yes, never two patterns or a pattern plus a generated image. Patterns render slowly, so render a section's background once per size, not on every resize.
- **Qbot, the logo and images** come from [`brand-assets/`](../brand-assets/) with their READMEs' rules. Qbot uses its own glow, `.qd-mascot--glow`.
- **Patterns** (Juan, 2026-11-21) bring the space, data and vector themes: the site should feel like space + data + vectors, for developers and enterprise. They live in [`patterns/`](patterns/), one file each, listed in `patterns/index.tsx`: **backgrounds** behind a section's content and **surfaces** inside its cards. The list is empty for now: the first set was removed so Juan can add patterns by hand, one at a time and with intent (2026-11-22). Don't add one unless he asks. A section takes them as props: `pattern` (an array of background ids) and `cardPattern` (one surface id), passed straight to `Section`; the builder sets them per section, and variants set none until Juan says. Never draw a pattern inside a section's own file: add it to `patterns/` so every section can use it. Patterns are still, subtle and in the website's variables (`--web-line`, `--web-indigo`, `--foreground`); no particle clouds, no twinkling, no glows beyond the horizon's rim. `data-web-patterns="off"` hides them all.
- **Cards are `Plate`s** ([`lib/plate.tsx`](lib/plate.tsx)): every card, panel and tile renders `<Plate as="li" …>`, never a div with `web-plate`, so the section's `cardPattern` reaches it. Media (code panels, image slots) keep `web-plate` as a class.
- **Icons have color, never amaranth** (Juan, 2026-11-21): an icon sits on an `IconTile` ([`lib/tone.tsx`](lib/tone.tsx)), a small tile tinted with a color family and a hairline in it, the icon in a solid color of the family (the 400 on dark, the 600 on light). Families: indigo (the default), teal, blue, purple, cyan, green, orange. Use one family for a set, or `toneAt(i)` to cycle for features of equal weight. Amaranth stays for the primary button and small brand marks; red for errors.
- **Indigo hints** (Juan, 2026-11-21): indigo is the website's second color, a thread through it: `--web-indigo` (indigo-400 on dark, 600 on light) for nodes, the active state of tabs and steps, link hovers and pattern accents. Never a flat fill behind text. `data-web-indigo="off"` keeps the hints neutral.
- **Lines and material** (Juan, 2026-11-21) are the library's shared, subtle structure, in [`styles/web.css`](styles/web.css). `Section` draws the lines: rails (a hairline down each side of the page, 24px outside the container), a seam between sections and a node where they meet; the kicker starts with the same node. A node is a small hexagon standing like the logo's brandmark, a point at the top and the bottom (Juan, 2026-11-22): always `Node` from [`lib/node.tsx`](lib/node.tsx) (`solid` over a line, `active` for the current step or tab), never a dot or a shape of your own. The material is classes: `web-plate` for cards and panels (a touch lighter at the top, a 1px inner highlight, a soft shadow on light), `web-tray` for a framed holder around media, `web-cells` for a hairline grid of facts, `web-rule` for a divider. A horizontal line inside a section takes `web-bleed` so it reaches the rails and the lines meet (Juan, 2026-11-21). The navbar and the announcement bar have no rails; the navbar keeps its bottom line. Use them instead of a new border or fill, so every section looks like one system. `data-web-lines="off"` and `data-web-material="off"` turn them off (the studio's Lines and Material switches).
- **Trial type** (Juan, 2026-11-21, a test): inside the website, headings start at 60px (H1 60, H2 52, H3 44, H4 38, H5 30, H6 22: the type set scaled by 60/64 with halves rounded to even, and H3 set to 44) with line heights from the type set's curve through H6 1.3 and H1 1.1 (1.1, 1.12, 1.14, 1.16, 1.21, 1.3), in Medium instead of SemiBold ([`styles/web.css`](styles/web.css); the heading classes in `lib/type.tsx` read `--web-heading-weight`). `data-web-type="current"` shows the type set as it is (the studio's Trial type switch). If it's kept, it moves into `primitives/typography` with Vanesa's yes.
- **Glows and textures belong in sections, not in components** (Juan, 2026-11-16). Components stay quiet; sections carry the brand moments. Build a section's glows, background lights and star fields in the section file with CSS (gradients, blur), in Qdrant palette colors through their variables, absolutely positioned behind the content, `aria-hidden` and `pointer-events-none`, and softer on light. Never inside a component in `design-system/`.
- **Amaranth is the web's accent** (marketing; product UI uses indigo, [`design-system/AGENTS.md`](../design-system/AGENTS.md)): buttons, highlights, small marks. Never a flat fill behind text, and no gradient on text ([`primitives/colors/`](../primitives/colors/)).
- **Take the Figma's colors for diagrams and icons** (Juan, 2026-11-16): use the palette color nearest to each Figma color (by OKLab distance), through its `--qd-color-*` variable, never a hex. That's the dark-theme value for fills, borders and dots. Icons and colored text keep the nearest family but take the contrast steps in [`primitives/colors/`](../primitives/colors/): 400 or lighter on dark, 600 for icons and 700 or darker for text on light. Give every color a `light:` value.
- **Copy:** never invent it. Use the copy you're given, or ask.
- **Dark and light, on the brand surfaces** (Juan, 2026-11-21). A page's root has `data-web` and a `data-theme`. Every section takes `theme` (dark or light, or the page's) and `surface` (`default` or `raised`), and `Section` sets them. Inside the website, [`styles/web.css`](styles/web.css) makes the design system's page, card, popover and highlight colors the background roles (`background/default`, `raised`, `overlay`, `highlight`), so the shadcn components in a section follow its theme and surface without any color of their own. On dark the website is quieter than the roles (Juan, 2026-11-21): menus and cards on neutral-925, highlights and hovers on neutral-900, a raised band's cards on neutral-900. A page loads `styles/web.css` after the design system's `globals.css`.
- **References are for patterns, never copies** (Juan, 2026-11-21). Mintlify, Exa, Supabase, Cloudflare, Neon and Giga inform layouts and patterns (hairlines over shadows, section headers with an action, cell grids, code beside its result). Never copy a layout one to one, their copy, illustrations or signature moves. The site must look like Qdrant and nobody else.
- **Every section has the shared props** from `lib/section.tsx` (`theme`, `surface`, `id`, `className`) and takes its content as props, so pages and the builder can fill it. Example content lives in [`content/`](content/): real qdrant.tech copy, verbatim. A slot the site has no copy for stays empty.
- **Use the helpers in `lib/`:** `Section` for every section (theme, surface, padding, the 1200px container or `narrow` or `full`), `SectionHeader` for a section's kicker, title, text and actions (stacked, split or with an action on the right), `heading` for responsive headings (page, section, statement, card) and `type` for text, `LinkButton` for every call to action, `Icon` for Lucide icons named in content, `Logo`, `CodePanel`, `CopySnippet`, `MediaFrame` for a media slot under review, `ArrowLink` for "Read more >" links, `Node` for the hexagon where lines meet and before kickers, steps and tabs, `ASSETS` for the path to `assets/`, `MonoImage` for a one-color image that follows the theme (social marks, badges), and `CloudLogo` for the AWS, Google Cloud and Azure logos.
- **Images from a Figma** (illustrations, customer and partner logos, social marks, certification badges) go in `assets/`, exported from the Figma as they are: SVG for vectors, PNG for the rest (Juan, 2026-11-16). Never redraw or recolor one; a one-color image takes the theme's color through `MonoImage` instead. The one exception is a logo whose maker has a version for light backgrounds, like `aws-on-light.svg`. Ask before adding a photo: the repo is public and holds no photos or working files. Product screens drawn in a Figma are rebuilt with the design system's components instead (in `data-context="product"`, so their accent is indigo).

## Adding a section

1. **The section**: one file in `sections/`, named for what it is (`hero.tsx`, `feature-grid.tsx`), one exported component that takes `SectionProps` plus its content, and passes `theme`, `surface`, `pattern`, `cardPattern`, `id` and `className` to `Section`. Layouts are a prop (`layout`), not separate files. Cards are `Plate`s; icons are `IconTile`s.
2. **Its registry entry**: a file in `registry/` with `defineSection`: its category, a one-line summary, its variants (ready-made props from `content/`, each with a name and a line on when to use it), its docs (when to use it, rules, anatomy, props) and the fields the page builder can edit. Add it to `registry/index.ts`. The studio's canvas, docs and builder read the registry, so a section without an entry doesn't exist for them.
3. **Check it** in the studio's Web page: every variant in the Docs tab, in dark and light, at desktop and phone width, then on the Canvas. Fix what reads wrong, then commit.

`web/sections` also holds the Resilience page's sections (`resilience-*`, `site-header`, `site-footer`, `cta-banner`), built before the library. They stay as a reference page until it's rebuilt from the library, then they go.

## Adding a pattern

One file in `patterns/` exporting `definePattern({ id, name, kind, description, Layer })`: `kind` is `"background"` (behind a section) or `"surface"` (inside each card). `Layer` is a component that fills its parent (absolute, inset 0), still and subtle, in the website's variables, in both themes. List it in `patterns/index.tsx`. It then shows in the studio's Patterns tab, in the builder's pattern pickers, and on any section through `pattern` or `cardPattern`.
