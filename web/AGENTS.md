# Web (for agents)

`@qdrant/web` is Qdrant's website section library: every section a site the size of qdrant.tech needs (navigation, heroes, features, proof, pricing, FAQ, calls to action, listings, footers and more), built from the [design system](../design-system/), with variants, docs and a page builder in the studio's Web page (Juan, 2026-11-21). The qdrant.tech website itself lives in another repo; this is where its sections are designed, documented and reviewed. The work is code-first: a section is built and approved here, and goes to Figma afterwards.

Read these first. Their rules apply here too:

1. The [root `AGENTS.md`](../AGENTS.md).
2. [`design-system/AGENTS.md`](../design-system/AGENTS.md), including which "Never" rules apply to web UI.

## Rules for sections

- **Build from the design system.** Import components from `@qdrant/design-system`. A section never sets its own colors, fonts or radii.
- **Page layout** follows [`primitives/spacing/`](../primitives/spacing/), "Web and landing page layout": a 1440px design width and a **1200px content container** (Juan, 2026-11-21; it was 1110px), 24px between columns, vertical section padding of 80 to 120px, never less than 80px, and 40 to 64px between a heading block and its content. `Section` applies it.
- **Breakpoints** come from [`primitives/breakpoints/`](../primitives/breakpoints/).
- **Pattern backgrounds** come from [`brand-assets/patterns/`](../brand-assets/patterns/), with its rules: they bleed off every edge, violet by default and red only with a yes, never two patterns or a pattern plus a generated image. Patterns render slowly, so render a section's background once per size, not on every resize.
- **Qbot, the logo and images** come from [`brand-assets/`](../brand-assets/) with their READMEs' rules. Qbot uses its own glow, `.qd-mascot--glow`.
- **Glows and textures belong in sections, not in components** (Juan, 2026-11-16). Components stay quiet; sections carry the brand moments. Build a section's glows, background lights and star fields in the section file with CSS (gradients, blur), in Qdrant palette colors through their variables, absolutely positioned behind the content, `aria-hidden` and `pointer-events-none`, and softer on light. Never inside a component in `design-system/`.
- **Amaranth is the web's accent** (marketing; product UI uses indigo, [`design-system/AGENTS.md`](../design-system/AGENTS.md)): buttons, highlights, small marks. Never a flat fill behind text, and no gradient on text ([`primitives/colors/`](../primitives/colors/)).
- **Take the Figma's colors for diagrams and icons** (Juan, 2026-11-16): use the palette color nearest to each Figma color (by OKLab distance), through its `--qd-color-*` variable, never a hex. That's the dark-theme value for fills, borders and dots. Icons and colored text keep the nearest family but take the contrast steps in [`primitives/colors/`](../primitives/colors/): 400 or lighter on dark, 600 for icons and 700 or darker for text on light. Give every color a `light:` value.
- **Copy:** never invent it. Use the copy you're given, or ask.
- **Dark and light, on the brand surfaces** (Juan, 2026-11-21). A page's root has `data-web` and a `data-theme`. Every section takes `theme` (dark or light, or the page's) and `surface` (`default` or `raised`), and `Section` sets them. Inside the website, [`styles/web.css`](styles/web.css) makes the design system's page, card, popover and highlight colors the background roles (`background/default`, `raised`, `overlay`, `highlight`), so the shadcn components in a section follow its theme and surface without any color of their own. A page loads `styles/web.css` after the design system's `globals.css`.
- **References are for patterns, never copies** (Juan, 2026-11-21). Mintlify, Exa, Supabase, Cloudflare, Neon and Giga inform layouts and patterns (hairlines over shadows, section headers with an action, cell grids, code beside its result). Never copy a layout one to one, their copy, illustrations or signature moves. The site must look like Qdrant and nobody else.
- **Every section has the shared props** from `lib/section.tsx` (`theme`, `surface`, `id`, `className`) and takes its content as props, so pages and the builder can fill it. Example content lives in [`content/`](content/): real qdrant.tech copy, verbatim. A slot the site has no copy for stays empty.
- **Use the helpers in `lib/`:** `Section` for every section (theme, surface, padding, the 1200px container or `narrow` or `full`), `SectionHeader` for a section's kicker, title, text and actions (stacked, split or with an action on the right), `heading` for responsive headings (page, section, statement, card) and `type` for text, `LinkButton` for every call to action, `Icon` for Lucide icons named in content, `Logo`, `CodePanel`, `CopySnippet`, `MediaFrame` for a media slot under review, `ArrowLink` for "Read more >" links, `ASSETS` for the path to `assets/`, `MonoImage` for a one-color image that follows the theme (social marks, badges), and `CloudLogo` for the AWS, Google Cloud and Azure logos.
- **Images from a Figma** (illustrations, customer and partner logos, social marks, certification badges) go in `assets/`, exported from the Figma as they are: SVG for vectors, PNG for the rest (Juan, 2026-11-16). Never redraw or recolor one; a one-color image takes the theme's color through `MonoImage` instead. The one exception is a logo whose maker has a version for light backgrounds, like `aws-on-light.svg`. Ask before adding a photo: the repo is public and holds no photos or working files. Product screens drawn in a Figma are rebuilt with the design system's components instead (in `data-context="product"`, so their accent is indigo).

## Adding a section

1. **The section**: one file in `sections/`, named for what it is (`hero.tsx`, `feature-grid.tsx`), one exported component that takes `SectionProps` plus its content. Layouts are a prop (`layout`), not separate files.
2. **Its registry entry**: a file in `registry/` with `defineSection`: its category, a one-line summary, its variants (ready-made props from `content/`, each with a name and a line on when to use it), its docs (when to use it, rules, anatomy, props) and the fields the page builder can edit. Add it to `registry/index.ts`. The studio's canvas, docs and builder read the registry, so a section without an entry doesn't exist for them.
3. **Check it** in the studio's Web page: every variant in the Docs tab, in dark and light, at desktop and phone width, then on the Canvas. Fix what reads wrong, then commit.

`web/sections` also holds the Resilience page's sections (`resilience-*`, `site-header`, `site-footer`, `cta-banner`), built before the library. They stay as a reference page until it's rebuilt from the library, then they go.
