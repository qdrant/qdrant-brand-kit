# Studio (for agents)

The studio is the workshop for the [design system](../design-system/) and the [web sections](../web/): a Next.js app that shows them on the real tokens, in dark and light. It isn't a website and never ships. Product pages come later.

Read the [root `AGENTS.md`](../AGENTS.md) and [`design-system/AGENTS.md`](../design-system/AGENTS.md) first.

## Rules

- **Every visual change is checked here before it's committed**, in dark and in light. Take screenshots to a folder outside the repo, never inside it.
- **The studio shows, it doesn't define.** A look decided here goes into the design system (`design-system/`) or the primitives, and gets a line in [`design-system/DESIGN.md`](../design-system/DESIGN.md). Nothing in `studio/` is a source of truth.
- **Run shadcn's CLI from here** (`pnpm dlx shadcn@latest add <name>`). It installs into the design system; then move the helpers it leaves in `studio/hooks` or `studio/lib` into the design system ([`design-system/AGENTS.md`](../design-system/AGENTS.md)).
- **Next.js 16 changed a lot.** Before writing app code, read the guide for what you're doing in `node_modules/next/dist/docs/`. `agentRules` is off in `next.config.ts`, so `next dev` never writes into `AGENTS.md`.
- **Themes:** `components/theme-provider.tsx` sets `data-theme` on `<html>`: dark by default; `d` or the moon and sun in the top menu switch it. Sections can set their own `data-theme`.
- **New component?** Add it to `lib/catalog.ts` and run `node studio/scripts/fetch-examples.mjs` for shadcn's demo. Never edit `examples/` by hand.
- **Changes come from prompts for now.** Juan changes the design system by prompting Claude Code with the studio open beside the chat, so the controls panel is hidden (2026-11-14). Make the change in `design-system/`, then check it in the studio in dark and light.
- **Controls** (the hidden DialKit panel) are global: they change CSS variables for every component, never one component. Define them in `lib/overrides.ts` (with the helpers in `lib/dials.ts`), on the design system's component tokens (`design-system/styles/components/`) and the primitives' steps, with defaults equal to the tokens' values so the panel starts with no changes. They only write a `<style>` tag while you try values. To keep one, put it in `design-system/` (or the primitives) and record it in `DESIGN.md`.
- **No glow in the design system's components** (Juan, 2026-11-14, narrowed 2026-11-16). Glows and similar effects (background lights, star fields, textures) are welcome in web sections and brand assets, built in the section with CSS from the Qdrant palette, never inside a component in `design-system/`.
- **Prototypes** (`lib/prototypes.ts`) are looks being compared, not decisions: each one overrides design-system tokens when its toggle beside the Overview heading is on. When Juan keeps one, write its values into `design-system/styles/components/`, add a dated line to `DESIGN.md`, and remove it from `lib/prototypes.ts`.
- **Variations** (`lib/variations.ts`, shown at `/variations`) are whole alternative looks, not decisions (Juan, 2026-11-15). They keep every color except the neutrals, and change structure through the design system's tokens. Use a variation's `css` only for a look no token covers yet, and say so. When Juan keeps one, or part of one, write it into `design-system/`, add a dated line to `DESIGN.md`, and add a token for anything that was in `css`.
- **Overview and Variations are product** (Juan, 2026-11-15): their components show the indigo accent, like the App pages. `useProductContext` (`components/product-context.tsx`) sets `data-context="product"` on `<html>` while the page is open, so menus and dialogs follow, and the page's root sets it too for the first paint. The Design system and Web pages stay marketing (amaranth).
- **Typography** (`/typography`) shows every text style in `primitives/typography/typography.css`, one tab per family of the Mona Sans family, each style in every weight it comes in, and the text in creatives and brand components at each shape's reference size (Creatives), to refine the type primitives (Juan, 2026-11-17). The proposed ladder had its own tab until Juan adopted it as the type set (2026-11-18). `lib/typography.ts` lists them: the `--qd-type-*` variables are read from the CSS and their weights from `qdrant.weights` in the token JSON, and the creative classes are listed by hand with the shapes that share a size, so update that list when a brand component's type changes. Each specimen measures its sample in the browser. Change type in the primitives or the brand components, never in the page.
- **Web pages** (`web/pages/`, shown at `/web/<page>`) put the sections from `web/sections` together into a marketing page, to see the design system on a real page (Juan, 2026-11-16). Take the layout and the copy from the Figma, exactly; use the design system's components, colors and Lucide icons. Add a route in `app/web/`. The Web link opens the Resilience page straight away (`app/web/page.tsx` redirects there); with more pages, add a way to switch between them on the page, like Variations.
- **App pages** (`product/`, shown at `/app`) rebuild Qdrant Cloud pages from the product's Figma, to see the design system in the product (Juan, 2026-11-15). Take the layout and the copy from the Figma, exactly. Never take its components, colors or icons: use the design system's components with their default look, our tokens, and Lucide (the nearest one when the Figma's icon isn't Lucide). Put the page inside `CloudShell` (`product/cloud-shell.tsx`), which sets `data-context="product"` so the accent is indigo, and add a route in `app/app/`. The App link opens the serverless space straight away (`app/app/page.tsx` redirects there, Juan, 2026-11-16); with more pages, add a way to switch between them on the page, like Variations.
- **Check your work visually:** with the Playwright MCP (see the README) or a browser, at `http://localhost:3000`, in dark and in light, and look at the pages you changed. Save screenshots outside the repo.
