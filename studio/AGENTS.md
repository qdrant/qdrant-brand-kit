# Studio (for agents)

The studio is the workshop for the [design system](../design-system/) and the [web sections](../web/): a Next.js app that shows them on the real tokens, in dark and light. It isn't a website and never ships. Product pages come later.

Read the [root `AGENTS.md`](../AGENTS.md) and [`design-system/AGENTS.md`](../design-system/AGENTS.md) first.

## Rules

- **Pages, in the top menu's order** (Juan, 2026-11-21): Overview, Design system (two tabs: Components, the list of components and each one's page, and Variations), Color, Typography, Web (Canvas, Docs, Pages, Builder), App and Space. The menu is `components/studio-nav.tsx`; the Design system tabs are `components/design-system-tabs.tsx`, on every page under `app/design-system/`.
- **Every visual change is checked here before it's committed**, in dark and in light. Take screenshots to a folder outside the repo, never inside it.
- **The studio shows, it doesn't define.** A look decided here goes into the design system (`design-system/`) or the primitives, and gets a line in [`design-system/DESIGN.md`](../design-system/DESIGN.md). Nothing in `studio/` is a source of truth.
- **Run shadcn's CLI from here** (`pnpm dlx shadcn@latest add <name>`). It installs into the design system; then move the helpers it leaves in `studio/hooks` or `studio/lib` into the design system ([`design-system/AGENTS.md`](../design-system/AGENTS.md)).
- **Next.js 16 changed a lot.** Before writing app code, read the guide for what you're doing in `node_modules/next/dist/docs/`. `agentRules` is off in `next.config.ts`, so `next dev` never writes into `AGENTS.md`.
- **Themes:** `components/theme-provider.tsx` sets `data-theme` on `<html>`: dark by default; `d` or the moon and sun in the top menu switch it. Sections can set their own `data-theme`.
- **New component?** Add it to `lib/catalog.ts` and run `node studio/scripts/fetch-examples.mjs` for shadcn's demo. Never edit `examples/` by hand. What Qdrant adds to a component (a variant, a state) gets its own demo in `components/qdrant-examples/`, listed in its `index.ts`, shown under shadcn's demos as "Qdrant variants" (Juan, 2026-11-21; the Alert's status variants first).
- **Changes come from prompts for now.** Juan changes the design system by prompting Claude Code with the studio open beside the chat, so the controls panel is hidden (2026-11-14). Make the change in `design-system/`, then check it in the studio in dark and light.
- **Controls** (the hidden DialKit panel) are global: they change CSS variables for every component, never one component. Define them in `lib/overrides.ts` (with the helpers in `lib/dials.ts`), on the design system's component tokens (`design-system/styles/components/`) and the primitives' steps, with defaults equal to the tokens' values so the panel starts with no changes. They only write a `<style>` tag while you try values. To keep one, put it in `design-system/` (or the primitives) and record it in `DESIGN.md`.
- **No glow in the design system's components** (Juan, 2026-11-14, narrowed 2026-11-16). Glows and similar effects (background lights, star fields, textures) are welcome in web sections and brand assets, built in the section with CSS from the Qdrant palette, never inside a component in `design-system/`.
- **Prototypes** (`lib/prototypes.ts`) are looks being compared, not decisions: each one overrides design-system tokens when its toggle beside the Overview heading is on. When Juan keeps one, write its values into `design-system/styles/components/`, add a dated line to `DESIGN.md`, and remove it from `lib/prototypes.ts`.
- **Variations** (`lib/variations.ts`, shown at `/design-system/variations`, the Design system page's second tab since 2026-11-21) are whole alternative looks, not decisions (Juan, 2026-11-15). They keep every color except the neutrals, and change structure through the design system's tokens. Use a variation's `css` only for a look no token covers yet, and say so. When Juan keeps one, or part of one, write it into `design-system/`, add a dated line to `DESIGN.md`, and add a token for anything that was in `css`.
- **Overview and Variations are product** (Juan, 2026-11-15): their components show the indigo accent, like the App pages. `useProductContext` (`components/product-context.tsx`) sets `data-context="product"` on `<html>` while the page is open, so menus and dialogs follow, and the page's root sets it too for the first paint. The Design system and Web pages stay marketing (amaranth).
- **Typography** (`/typography`) shows every text style in `primitives/typography/typography.css`, one tab per family of the Mona Sans family, each style in every weight it comes in, and the text in creatives and brand components at each shape's reference size (Creatives), to refine the type primitives (Juan, 2026-11-17). The proposed ladder had its own tab until Juan adopted it as the type set (2026-11-18). `lib/typography.ts` lists them: the `--qd-type-*` variables are read from the CSS and their weights from `qdrant.weights` in the token JSON, and the creative classes are listed by hand with the shapes that share a size, so update that list when a brand component's type changes. Each specimen measures its sample in the browser. Change type in the primitives or the brand components, never in the page.
- **Color** (`/color`) is where the palette and its rules are worked on (Juan, 2026-11-19). Its tabs: **Palette**, the brand's colors as 10 steps per color like Geist's (1–3 backgrounds, 4–6 borders, 7–8 solids, 9–10 text) that keep their job in light and dark, built from the primitives; one tab per group of the Color collection in the Figma file "Qdrant Brand Design" (2u6KfDsYjibQuf9ji6lFBR): **Text**, **Primary**, **Secondary**, **Status**, **Background**, **Border**, **Data viz** and **Static**, each with how to use it, its tokens in light and dark with their contrast and what the repo has today, and the tokens at work in both themes (Juan, 2026-11-21); and **Assets**, example assets drawn only from the semantic tokens, which the page's panel remaps live. `lib/color.ts` holds the palette, the tokens (`semanticTokens`, with Figma's names, values and code syntax, read 2026-11-21; read them again when the file changes) and each group's guide (`groupGuides`); `app/color/layout.tsx` writes the steps as `--qd-palette-<family>-<step>` (`palette/<family>/<step>` in Figma). Figma groups the brand accents as `primary/*` and `secondary/*`, and `primitives/colors` has the same roles and values (Juan, 2026-11-21), so the tabs' "Repo today" column should say "Same" everywhere; anything else is drift to fix. Every step is a primitive; each color got a 975 for dark backgrounds, like neutral-975, and no other new primitive (Juan, 2026-11-19). Semantic tokens point at a primitive in each theme, never at a palette step, so changing the palette never moves them (Juan, 2026-11-19; the same rule as Figma's Color collection). Panel changes stay in the browser; "Copy changes" gives the list to paste into the chat. When Juan keeps a step or a token, it goes into `primitives/colors` (and Figma), with Vanesa's yes.
- **Web** (`/web`, Juan, 2026-11-21) shows the website section library (`web/`) in four tabs. **Canvas**: every section and variant side by side at 1440px, one row per section, like a Figma page. The sections are live (hover the navbar for its menus); scroll to pan and Ctrl or Cmd with the wheel to zoom anywhere, frames included (they pass the wheel on); drag an empty area or hold Space to pan, or pick the hand tool. Dark, light or both, and the Lines and Material switches, are in its toolbar (also in Docs and the Builder). Frames hide Next.js's dev indicator. **Docs**: one section at a time, with a sidebar of all of them, its summary, when to use it, rules, anatomy, props and every variant in dark and light at desktop or phone width; the team and agents read it. **Pages**: whole pages from `web/pages` (the Resilience page, a reference). **Builder**: put a page together from the library (layers and the library on the left, the page at desktop, tablet or phone width in the middle, the selected section's variant, theme, surface and text on the right); pages are kept in the browser, and Copy TSX gives a page component for `web/pages`. All three read `web/registry`. Previews are iframes of `/web/frame` (no studio menu), so each has its own width and theme and reports its height; `components/web/` holds the views.
- **Space** (`/space`) explores the space theme for web sections (Step 9, 2026-11-18, second round 2026-11-19): 20 backgrounds, 20 signature visuals, 20 card surfaces and 20 WebGL shaders, each with a code to point at it (BG-07, SH-12), and a few of them on real sections. They are options to compare, not decisions. `lib/space.ts` lists the first round and merges each tab's `components/space/<tab>/options.ts`; `components/space/` draws them (canvas, WebGL, SVG and CSS) on the palette through the `--sp-*` variables in `app/space/space.css`, in dark and light, only while on screen, and still for reduced motion. A shader holds its WebGL context only while it's near the screen (browsers keep about 16). When Juan keeps one, move it to `web/` (never into a design-system component) and add a dated line to `DESIGN.md`.
- **App pages** (`product/`, shown at `/app`) rebuild Qdrant Cloud pages from the product's Figma, to see the design system in the product (Juan, 2026-11-15). Take the layout and the copy from the Figma, exactly. Never take its components, colors or icons: use the design system's components with their default look, our tokens, and Lucide (the nearest one when the Figma's icon isn't Lucide). Put the page inside `CloudShell` (`product/cloud-shell.tsx`), which sets `data-context="product"` so the accent is indigo, and add a route in `app/app/`. The App link opens the serverless space straight away (`app/app/page.tsx` redirects there, Juan, 2026-11-16); with more pages, add a way to switch between them on the page, like Variations.
- **Check your work visually:** with the Playwright MCP (see the README) or a browser, at `http://localhost:3000`, in dark and in light, and look at the pages you changed. Save screenshots outside the repo.
